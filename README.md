## v1.58 更新内容

### 1. 取消模板表头加"*"标记（根源避免导入识别问题）
- **去掉表头" *"后缀**：导出模板时不再给必填列表头添加" *"（如"班级 *"→"班级"），从根源上避免导入识别问题
- **改为批注提示**：必填项用红色字体显示表头，鼠标悬浮时批注提示"※必填项"
- 之前v1.57的 `normalizeHeader()` 函数仍然保留作为兜底防护（处理用户自己修改表头的情况）

### 2. 导入后自动数据清洗（防止用户输入不规范）
- **新增 `cleanScore()` 函数**：对导入的每个成绩值进行清洗
  - 全角字符转半角（如"Ａ62"→"A62"→提取62）
  - 去除所有空格、制表符（如" 87.5 "→"87.5"）
  - 提取数字部分，忽略其他字符（如"62分"、"62.5分*"→提取数字）
  - 空值、null、非数字字符串返回null（标记为空成绩）
- **统一调用**：`parseWorkbook()` 中成绩解析和总分解析都使用 `cleanScore()`
- **测试验证**：13种输入变体全部正确处理

### 3. 模板"软件使用流程"文字美化
- **标题行**（下载模板、导入数据等）：加粗+蓝色（#1E40AF）+浅蓝底（#DBEAFE），更醒目
- **说明行**：普通字体+深灰色（#475569）+浅灰底，层次分明
- 步骤号：白字蓝底（保持），字号增大到12

## v1.56 更新内容

### 修复导入模板无法识别的严重bug（核心修复）
- **问题根因**：v1.41导出模板时，必填列表头会添加" *"后缀（如"班级 *"、"语文 *"、"姓名 *"），但导入时 `parseWorkbook()` 和 `identifySheets()` 用精确匹配 `==='班级'`，无法识别"班级 *"，导致：
  - 提示"列"班级*含非成绩关键词，已排除"
  - 提示"缺少科目:语文(无此列)、数学(无此列)、英语(无此列)"
  - 提示"未检测到有效学生数据"
- **修复方案**：在 `identifySheets()` 和 `parseWorkbook()` 的4处表头读取位置，统一添加 `.replace(/\s*\*\s*$/,'')` 清理末尾的" *"后缀
  - identifySheets第698行、第723行：清理表头后匹配"班级"和科目
  - parseWorkbook第768行：找表头行时清理
  - parseWorkbook第770行：构建cm列名映射时清理
- **修复效果**：导出的模板文件现在可以正确导入识别，"班级 *"→"班级"、"语文 *"→"语文"，所有列名匹配正常工作

## v1.53 更新内容

### 1. 修复成绩校验弹窗被覆盖的bug（核心修复）
- **问题根因**：v1.52的`validateScores()`在`parseWorkbook()`后同步执行并显示校验弹窗，但`parseWorkbook()`内部通过`setTimeout(showExamTitleConfirm, 300)`延迟300ms显示"考试名称确认"弹窗，**导致300ms后考试名称弹窗覆盖了校验弹窗内容**，造成"未检测出"的假象
- **弹窗队列机制**：引入`modalQueue`队列和`showModal()`统一函数，弹窗按顺序显示，后显示的弹窗自动排队等待前一个关闭后再显示
- **校验逻辑本身正确**：v1.52的直接检查`sc===0||sc==null||isNaN(sc)`逻辑无误，覆盖空单元格和0分两种情况

### 2. 配置区布局重构
- **3等列布局**：积分比例、档位比例、奖励比例三个比例区一行等宽显示（`repeat(3,1fr)`），视觉更整齐
- **积分比例两行布局**：按用户建议，人均独占第一行，A档+B档第二行两等列，避免3个数字框挤在一行

## 部署方法

### 方法一：手动部署

1. 将 `deploy/` 文件夹中的所有文件上传到GitHub仓库
2. 在仓库 Settings → Pages 中选择 main 分支
3. 访问 `https://用户名.github.io/仓库名/`

### 方法二：使用构建脚本

1. 修改 `source_v1.58源码.html` 源代码
2. 运行 `python build_deploy.py` 生成加密部署版
3. 将 `deploy/` 文件夹内容上传到GitHub
